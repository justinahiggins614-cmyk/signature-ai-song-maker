# Signature Music Studio — API / machine-access guide

Base URL: `https://justinahiggins614-cmyk.github.io/signature-ai-song-maker/`
Repo: `https://github.com/justinahiggins614-cmyk/signature-ai-song-maker`

## Exact-ID queries

One record, exact ID, rendered as a full record page with lens-style detail,
audio render buttons, Q&A, copy/download, read-aloud, and per-record
JSON-LD (`MusicRecording`, no license field):

- Song: `?song=JAH-SONG-0000001`
- Sound: `?sound=JAH-SOUND-0000001`
- Equipment: `?gear=JAH-GEAR-0000001`
- Beat: `?beat=JAH-BEAT-0000001`

The router (`assets/app.js` `route()`) reads exactly one of those four
params. An unknown ID renders "Record not found." IDs are case-sensitive and
must match `^JAH-(SONG|SOUND|GEAR|BEAT)-\d{7}$`.

## Raw JSON endpoints

| Endpoint | Shape | Notes |
|---|---|---|
| `music-manifest.json` | The source of truth: counts, ID ranges, engine version, voices, index sha256, deep links, provenance | Regenerated by `code/build_site_files.py` after every drip. Schema: `schemas/music-manifest.schema.json` |
| `data/music-catalog.json` | `{"site","updated","counts","records":[{id,kind,title,chunk,url}]}` | One entry per record; `chunk` names the record chunk file; `url` is the absolute deep link |
| `api.json` | Site identity, counts, ID schemes, deep links, sitemap list | Also regenerated per drip |
| `data/index/index.json.gz` | JSONL, gzipped. Rows: `[id, title, kind, chunk]` | The compact index the page loads first. The "title" column holds `title` for songs and `name` for sounds/beats. Schema of the row format is in the manifest (`index.row_format`) |
| `data/records/recs-cNNNNN.json.gz` | JSONL, gzipped: one full record object per line | Chunks of 100 records (`code/drip.py` `CHUNK`) |

## How index rows map to chunks

1. Find the row for the ID in `data/index/index.json.gz`: row =
   `[id, title, kind, chunk]`.
2. Fetch `data/records/<chunk>` (row index 3), gunzip, split into lines;
   each line is one full record JSON object.
3. Return the line whose `"id"` equals the requested ID.
4. If the chunk fetch fails or no line matches (stale pointer), the page
   falls back to **deterministic regeneration** from the ID number
   (`assets/app.js` `detGen` → `SigData.gen(kind, n)`) — the same record the
   archive holds, recomputed from the seed.
5. Precedence note: during a visit, AI-written songs resolve through the
   session registry (`window.__genSongs`) to the *exact* record the user saw
   — same ID and seed, but with the user's title/theme rather than the
   archive's deterministic title.

Chunk pointers are verified per drip (`music-manifest.json`
`index.chunk_pointers_verified: true`).

## Sitemaps

`sitemap.xml` (= `sitemap-index.xml`) lists `sitemap-core.xml`
(9 studio sections) + `sitemap-songs.xml` + `sitemap-library.xml` +
`sitemap-beats.xml` + `sitemap-gear.xml` — one URL per record deep link.
`robots.txt` points at the index.

## Provenance fields on every record

The record panel (`assets/app.js` `recPanelHTML`) shows, and agents may rely
on:

- `STATUS`: `SIGNATURE ORIGINAL` (equipment) or `GENERATED` (song/sound/beat)
- `ID`: the permanent record ID
- `VERSION`: `v1.0`
- `SOURCE`: `Signature Music Studio · studio engine`
- Seed line: *"reproducible seed **n** — the same ID always makes this exact
  record."*

The embedded JSON-LD is `@type: MusicRecording` with `name, identifier,
byArtist (Person "Justin Addam Higgins"), description, url`, plus a computed
`duration` (bars × tempo estimate, never a claimed audio file), `genre`, and
`recordingOf` for songs. **There is no `license` field — do not add one.**

See `RECORD-STANDARD.md` for the full record law and `DETERMINISM.md` for
the reproducibility contract.
